## 🔴 Temuan Kritis / Tinggi

### 1. Default password admin hardcoded di seeder
**Lokasi:** `api-almuhsin-app/database/seeders/RoleAndAdminSeeder.php:33-39`

```php
$admin = User::firstOrCreate(
    ['email' => 'admin@almuhsin.app'],
    ['name' => 'Super Administrator', 'password' => Hash::make('password123')]
);
```

Akun Super Admin dibuat dengan password `password123`. Jika seeder ini pernah dijalankan di produksi dan password tidak segera diganti, siapapun yang tahu alamat login bisa masuk sebagai Super Admin. Ini **default credential** klasik.

**Rekomendasi:** jangan simpan default password di seeder; gunakan env (`ADMIN_DEFAULT_PASSWORD`) yang wajib diisi, atau paksa ganti password saat login pertama.

### 2. Token Sanctum tidak pernah kedaluwarsa
**Lokasi:** `api-almuhsin-app/config/sanctum.php:53` → `'expiration' => null`

Token hasil login (`createToken('auth_token')`) berlaku **selamanya** — tidak ada `expires_at`. Dampak:
- Seluruh alur auto-refresh `POST /refresh` di frontend (interceptor 401) praktis **tidak pernah terpicu** (token tak pernah 401 karena kedaluwarsa).
- Token yang bocor/tercuri = akses permanen sampai user logout manual / token dicabut.

**Rekomendasi:** set `'expiration' => 60 * 24` (mis. 1 hari) atau `expires_at` per token, lalu andalkan `POST /refresh` (sudah terimplementasi) untuk rotasi.

### 3. 🔴 Tarik data tidak menyimpan `tingkat` (bug lama, MASIH ada)
**Lokasi:** `api-almuhsin-app/app/Services/StudentService.php`
- `pullSelectedStudents()` (baris 114–127) — `updateOrCreate` **tidak** menulis `tingkat` (padahal `StudentRequest`/frontend mengirimnya, dan `Student::$fillable` sudah mencakup `tingkat`).
- `syncWithExternal()` (baris 163–172) — juga **tidak** menulis `tingkat`. Hanya `syncAllWithExternal()` (baris 229) yang benar.

**Dampak:** santri hasil tarik data kehilangan tingkat → kolom "Tingkat" & filter tingkat mati. **Ini persis Bug #1 di `AUDIT-BACKEND-2026-08-12.md`, belum diterapkan.**

**Rekomendasi:** tambah `'tingkat' => $data['tingkat'] ?? null` di `pullSelectedStudents()` dan `'tingkat' => $externalData['tingkat'] ?? $student->tingkat` di `syncWithExternal()`.

### 4. 🔴 Ringkasan presensi H/I/S/A selalu 0 (bug lama, MASIH ada)
**Lokasi:** `api-almuhsin-app/app/Services/AttendanceService.php:76`

```php
$query = AttendanceSession::with(['academicYear', 'classRoom', 'user'])  // ← tanpa 'records'
```

List presensi tidak eager-load `records`, sehingga `AttendanceResource` (yang memakai `whenLoaded('records')`) mengembalikan array kosong. Akibatnya ringkasan Hadir/Izin/Sakit/Alfa di tabel riwayat, rekap harian & bulanan **selalu 0**.

**Rekomendasi:** ubah jadi `->with(['academicYear', 'classRoom', 'user', 'records'])`. **Ini persis Bug #2 audit sebelumnya.**

## 🟠 Temuan Sedang

### 5. Bocor pesan exception ke klien (info disclosure)
Hampir semua controller mengembalikan `$e->getMessage()` mentah, mis.:
- `AuthController::login` (baris 34–37), `StudentController::searchExternal/pullExternal/sync` (baris 103, 126, 145), `AttendanceController::store` (baris 51–54), `PhoneCollectionController` (baris 52–54), `AcademicYearController::getActive` (baris 67), dst.

Pesan error database/stack (terutama saat `APP_DEBUG=true`) bocor ke klien — mempermudah reconnaissance. **Rekomendasi:** log detail ke `Log::error(...)`, balas klien dengan pesan generik (atau pesan bisnis yang sudah jelas), jangan `$e->getMessage()`.

### 6. `APP_DEBUG=true` di `.env.example`
**Lokasi:** `api-almuhsin-app/.env.example:4`. Pastikan `.env` produksi memakai `APP_DEBUG=false` (bila `true`, stack trace + query bocor lewat respons error, memperparah temuan #5). Backend `.env` sendiri untungnya **tidak ter-commit** (`.gitignore` benar).

### 7. FK `student_id` masih cascade — riwayat ikut terhapus saat santri dihapus
Kebijakan `nullOnDelete` diterapkan ke FK `user` & `teacher`, tapi **tidak** ke `student`:

| Tabel | Kolom | Kondisi | Akibat |
|---|---|---|---|
| `student_leaves` | `student_id` | `cascadeOnDelete` (sengaja, lihat `2026_08_09...fix_uuid_columns` baris 29) | hapus santri → izin hilang |
| `phone_collections` | `student_id` | `cascadeOnDelete` (migration awal, tak pernah diubah) | hapus santri → riwayat HP hilang |
| `attendance_records` | `student_id` | `cascadeOnDelete` (migration awal) | hapus santri → rekap presensi hilang |

Ini **bertentangan** dengan `api_documentation_keamanan.md` §7 ("Tangani relasi null: … `student` … bisa `null` jika data induknya dihapus") dan frontend yang sudah menyiapkan fallback `student: null`. Guru sudah benar (`teacher_id` → `nullOnDelete`), santri belum.

**Rekomendasi (butuh keputusan produk):** samakan — bila ingin riwayat dipertahankan (konsisten dengan guru), ubah ketiganya ke `nullOnDelete` via migration baru. Bila memang ingin hapus jejak, perbaiki docs & hapus fallback `student: null` di frontend agar tidak membingungkan.

### 8. Daftar invoice implisit terbatas bulan berjalan
**Lokasi:** backend `InvoiceService::getAll` (baris 18–20) default `month=date('m')` / `year=date('Y')`; frontend `invoice-page.jsx` memanggil `useInvoices()` **tanpa** param dan **tidak ada** pemilih bulan/tahun di UI.

**Dampak:** invoice bulan lalu (termasuk status "Tunggakan"/"Jatuh Tempo") tidak pernah tampil. Tagihan yang belum lunas jadi "menghilang" dari list begitu ganti bulan.

**Rekomendasi:** tambah filter bulan/tahun di UI invoice (kirim `month`/`year`), atau ubah default backend agar tidak memfilter bulan bila tidak diminta.

### 9. `.env` frontend ter-commit ke git
**Lokasi:** `almuhsin-app/.env` (ter-track — `git ls-files` menunjukkan `.env`). Isi saat ini hanya `VITE_APP_NAME` + `VITE_API_URL` (bukan rahasia), tapi kebiasaan ini berbahaya: begitu ada `VITE_*` sensitif (mis. API key) terselip, langsung bocor ke repo publik.

**Rekomendasi:** `git rm --cached .env`, tambahkan `.env` ke `.gitignore`, sediakan `.env.example`.

## 🟡 Temuan Rendah / Informasional

10. **Rate limiting hanya di `/login`** (`routes/api.php:21`). Endpoint lain (termasuk `/refresh`, `external-pull`, `external-sync` yang menyentuh API eksternal) tanpa throttle — bisa di-spam.
11. **Tidak ada `config/cors.php`** → Laravel default `Allow-Origin: *`. Aman untuk API Bearer-token (tanpa cookie), sekedar catatan bila nanti beralih ke cookie.
12. **`payment_method` tidak di-validasi enum** (`PaymentRequest.php:20` hanya `string|max:50`; `PaymentService` hanya `strtoupper`). Nilai selain `TUNAI/TRANSFER/SALDO` tersimpan apa adanya.
13. **Email guru immutable** — `TeacherRequest` pada PUT tidak punya aturan `email`, `TeacherService::update` tidak menyentuh email. (Satpam mendukung ganti email; guru tidak — tidak konsisten.)
14. **`student-leaves` & `teacher-attendances` mengembalikan model mentah** (bukan Resource): `StudentLeaveController::index` mengembalikan `$data->items()` raw, `store/update` mengembalikan `$leave` raw. Tidak berbahaya (relasi `student`/`user` sudah di-load), tapi tidak konsisten dengan resource-based controller lain & rentan bocor kolom baru di masa depan.
15. **Dead code frontend** (tidak diimpor siapa pun):
    - `src/app/store/auth-store.js` (duplikat store auth — yang aktif `features/auth/stores/auth-store.js`)
    - `src/services/api/token.js` (duplikat — aktif `features/auth/lib/token.js`)
    - `src/features/auth/api/auth.js` (`loginRequest`/`meRequest` — aktif `features/auth/services/auth.service.js`)
    - `src/constants/dummy-user.js`
16. **`useInvoices` memakai `placeholderData: (previous) => previous`** — pola ini (per pitfall tarik-data) menyembunyikan loading jujur; dampak kecil karena invoice tak ada filter, tapi sebaiknya dihapus.

## ✅ Hal yang SUDAH Benar (tidak perlu diubah)

- **Mass assignment aman**: semua model pakai `$fillable` whitelist, semua controller pakai `$request->validated()`; `balance` santri tidak bisa diset via API; `user_id`/`recorded_by`/`receiver_id`/`returner_id` di-set server-side.
- **Route guard per role** konsisten (`Super Admin|Ustadz|Bendahara|Keamanan`) di backend + `RoleGuard` frontend.
- **API key induk** (`INDUK_API_KEY`) dipakai server-side via `config('services.induk')` — tidak bocor ke frontend.
- **`syncAllWithExternal`** konkuren (`Http::pool`) + respons `{total, updated, failed}`.
- **Frontend normalisasi API v2** (`listData`/`listPagination`) + fallback `records ?? students ?? details` sudah diterapkan; grep pemanggil getter langsung bersih.
- **CRUD lengkap** perizinan/presensi-guru/HP (delete ada, sesuai docs).
- **Backend `.env`** ter-gitignore; migrasi perbaikan FK `user_id`/`teacher_id` → `nullOnDelete` sudah rapi (deteksi nama constraint MySQL via `information_schema`).
