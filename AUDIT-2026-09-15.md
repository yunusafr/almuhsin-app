## 🔴 Temuan Tinggi

### 1. Refresh token tidak berfungsi — user dipaksa login ulang tiap 24 jam (lintas-stack)

**Akar masalah:** perbaikan #2 (token kedaluwarsa 24 jam) digabung dengan alur refresh yang salah desain.

- **Backend** (`routes/api.php:24-27`): `POST /refresh` berada di dalam `Route::middleware('auth:sanctum')`. Artinya, untuk me-refresh token, request **harus membawa token yang masih valid**.
- **Frontend** (`src/services/api/axios.js:48-100` & `src/features/auth/lib/axios.js:46-88`): interceptor hanya memanggil `/refresh` **setelah menerima 401** — yaitu saat token **sudah kedaluwarsa**. Token kedaluwarsa itu yang dikirim ke `/refresh`.

**Alur nyata setelah token berumur >24 jam:**
1. Request → backend `auth:sanctum` → **401** (token expired).
2. Interceptor panggil `/refresh` dengan token expired yang sama.
3. `/refresh` (di-gate `auth:sanctum`) → **401** lagi.
4. `refreshPromise` gagal → `removeToken()` → redirect `/login`.

**Dampak:** fitur auto-refresh **tidak pernah berhasil** (kode mati), dan semua user **dipaksa login ulang setiap 24 jam** — meski sedang aktif. Ini regresi fungsional dari "fix" kedaluwarsa.

**Rekomendasi (butuh keputusan arsitektur):**
- **(a)** Terapkan *refresh token* terpisah yang berumur panjang (bukan access token), atau
- **(b)** `/refresh` menerima token expired dengan masa tenggang (grace period) + validasi `hash_equals`, atau
- **(c)** Frontend *proaktif* me-refresh **sebelum** kedaluwarsa (cek umur token, bukan reaktif saat 401), atau
- **(d)** Paling sederhana: kembalikan `expiration => null` jika rotasi tidak benar-benar dibutuhkan (menerima trade-off temuan #2 lama).

## 🟠 Temuan Sedang

### 2. `$e->getMessage()` masih bocor lewat try/catch controller (16 tempat)

Global exception handler di `bootstrap/app.php` hanya menjangkau exception yang **tidak tertangkap**. Controller berikut menangkap `\Exception` sendiri lalu mengembalikan pesan mentah — melewati pemeriksaan `APP_DEBUG`:

```
AcademicYearController.php:67,92      AttendanceController.php:53
AuthController.php:36                 ClassEnrollmentController.php:42,60,85
InvoiceController.php:65              PaymentController.php:37
PhoneCollectionController.php:54,71,108,124
StudentController.php:104,126,145
```

Pesan error DB/PDO (terutama `StudentService::syncWithExternal` yang melemparkan `'… ' . $e->getMessage()`) tetap bocor ke klien meski `APP_DEBUG=false` di produksi.

**Rekomendasi:** di catch controller, `Log::error($e)` lalu balas `message` bisnis yang jelas (atau `'Terjadi kesalahan. Silakan coba lagi.'`). Exception bisnis yang disengaja (mis. "Kredensial tidak valid", "Presensi sudah dicatat") boleh tetap dikembalikan — pisahkan dengan `catch (\Exception)` khusus untuk error tak terduga.

### 3. Dua instance axios paralel dengan interceptor divergen

- `src/services/api/axios.js` → dipakai 13 modul API (semua feature). Punya handler **401 refresh + 429 toast**.
- `src/features/auth/lib/axios.js` → dipakai `auth.service.js` (login/me/logout/refresh). **Tidak punya handler 429**.

Konsekuensi: login lewat rate-limit (`throttle:5,1`) menghasilkan 429 yang **tidak di-toast** di jalur auth. Duplikasi berarti tiap perbaikan interceptor harus dikerjakan dua kali (dan keduanya sudah drift).

**Rekomendasi:** satu instance axios (`services/api/axios.js`) sebagai satu-satunya klien; `auth.service.js` mengimpor dari sana. Gabungkan kedua `lib/token.js` (key-nya sama `almuhsin_token`, jadi aman).

### 4. `baseURL` API hardcoded; `VITE_API_URL` tidak dipakai

`BASE_URL` di-hardcode di **kedua** file axios (baris 5 & 4). `.env`/`.env.example` mendefinisikan `VITE_API_URL` tapi **tidak pernah dibaca** (`import.meta.env` tidak muncul di mana pun). `.env.example` bahkan mencatat hal ini sebagai "disediakan untuk refactor nanti".

**Rekomendasi:** `baseURL: import.meta.env.VITE_API_URL || "https://api-almuhsin.ingintau.my.id/api/v1"` — satu sumber kebenaran, plus fallback agar build tak pernah mengarah ke origin SPA.

## 🟡 Temuan Rendah / Informasional

5. **Artefak test di root backend** — `test_attendance.php` & `test_laravel.php` ter-commit. `test_attendance.php` meng-`INSERT` data presensi bila diakses; `test_laravel.php` mencetak nama user pertama. Tidak web-accessible bila docroot benar (`public/`), tapi berbahaya bila docroot salah konfigurasi di shared hosting. **Hapus keduanya.**

6. **Email guru immutable** — `TeacherRequest` (PUT/PATCH) tidak punya aturan `email`, `TeacherService::update` tidak menyentuh email; sementara `SecurityGuardRequest` mendukung ganti email. Tidak konsisten.

7. **`balance` ada di `$fillable` Student** — saat ini aman karena `StudentRequest` tidak memvalidasi `balance` dan `pullSelectedStudents` menulis field eksplisit. Tetap disarankan `$guarded = ['balance']` sebagai lapis kedua (defense-in-depth) agar tak bisa diset lewat jalur masa depan.

8. **`payment_method` tidak di-enum-validasi** — `PaymentRequest` hanya `string|max:50`; `PaymentService` hanya `strtoupper`. Nilai selain `TUNAI/TRANSFER/SALDO` tersimpan apa adanya. Tambah `Rule::in(['TUNAI','TRANSFER','SALDO'])`.

9. **Rate limiting hanya di `/login`** — `/refresh`, `/me`, `students/external-search|pull|sync` (yang menembak API induk) tanpa `throttle`. Tambah `throttle:30,1` untuk lookup/enumeration & endpoint eksternal.

10. **Tanpa `config/cors.php`** — default `Allow-Origin: *`. Aman untuk API bearer-token (tanpa cookie); catatan saja.

11. **Dead code frontend** (tidak diimpor siapa pun):
    - `src/App.jsx` (stub — `main.jsx` pakai `router` langsung)
    - `src/app/store/auth-store.js` (duplikat; aktif `features/auth/stores/auth-store.js`)
    - `src/app/store/theme-store.js` (duplikat; aktif theme-provider + use-theme-toggle)
    - `src/features/auth/api/auth.js` (`loginRequest`/`meRequest`)
    - `src/constants/dummy-user.js`, `src/features/santri/data/dummy-santri.js`

    > Catatan koreksi: `src/services/api/token.js` **TIDAK** dead (dipakai `services/api/axios.js` via `./token`) — berbeda dengan klaim audit 3 Sept.

12. **Tanpa ErrorBoundary / `errorElement`** — router (`createBrowserRouter`) tidak punya `errorElement` dan tidak ada class boundary. Render error apa pun → stack dump bawaan React Router. Tambah `RouteError` (route-level) + boundary di `main.jsx`.

13. **`.hermes/` tidak di `.gitignore`** — folder mock muncul sebagai untracked noise (`?? .hermes/`). Tambahkan ke `.gitignore`.

14. **Divergensi nama role** (backend `"Ustadz"` ↔ frontend `"Asatidz"`) — berfungsi benar lewat alias `normalizeRoles` (`ustadz→Asatidz`), dan seeder backend sudah migrasi `Asatidz→Ustadz`. Hanya potensi salah paham bagi developer baru. Disarankan samakan ke satu nama.

## ✅ Hal yang Sudah Benar (tidak perlu diubah)

- **Mass assignment aman**: semua controller pakai `$request->validated()` (grep `$request->all()` → 0 hasil); `$fillable` whitelist; `user_id`/`recorded_by`/`receiver_id`/`returner_id`/`recorded_by` di-set server-side.
- **PaymentService** solid: `lockForUpdate()` anti race-condition, transaksi DB, alur `SALDO`/lebih bayar → saldo siswa, nomor kuitansi unik.
- **SecurityGuardService**: `findById` menolak id non-role `Keamanan` (anti-IDOR antar-role), hapus → cabut semua token.
- **ClassEnrollmentService**: cek duplikat (tahun+santri) sebelum insert, `bulkCreate` lewati yang sudah terdaftar.
- **Role guard route** konsisten backend (`Super Admin|Ustadz|Bendahara|Keamanan`) + `RoleGuard` frontend (dengan alias).
- **`syncAllWithExternal`** konkuren (`Http::pool`) + respons `{total, updated, failed}`; API key induk via `config('services.induk')` (tidak hardcoded).
- **Normalisasi API v2** (`listData`/`listPagination`) + interceptor 401 refresh & 429 toast (di instance utama).
- **Toaster** ter-mount di `main.jsx`; `listData` defensif terhadap 3 bentuk respons.
- **Resource** redaksi PII wajar (relasi `whenLoaded`, tanpa `password`), tak ada endpoint publik (semua di balik `auth:sanctum`).
